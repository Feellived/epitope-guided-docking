# 00. VSCode로 파이썬(.py) 편집·실행하기 — 완전 초보 워크플로 (macOS)

> ⚠️ **이 문서는 2026년 6월 시점 기준이며 이후 갱신하지 않았다.**
> 현재 파이프라인은 `pipeline/` 에 있다. 배경은 `legacy_af3/README.md` 참조.

이 문서는 지금까지 **주피터(Jupyter) / 구글 코랩(Colab)** 만 써온 사람이,
**".py 파일을 VSCode에서 편집 → 터미널에서 실행"** 하는 방식으로 넘어오는 전체 흐름을
손으로 한 번씩 따라 할 수 있게 정리한 것이다.

대상 환경: macOS (zsh 셸), 로컬 맥 + 연구실 리눅스 서버(ssh 접속).
서버 접속·파일 전송의 상세는 `docs/03_서버_ssh_scp_tmux.md` 참조.

> 참고: VSCode의 메뉴·버튼 이름, 신뢰 프롬프트 문구 등은 **VSCode 버전·언어 설정**에
> 따라 조금씩 다를 수 있다. 아래는 영어 UI 기준의 일반적인 명칭이며, 못 찾겠으면
> 명령 팔레트(`Cmd+Shift+P`)에서 같은 이름을 검색하면 대개 나온다.

용어 미리 풀이:

- **셸(shell):** 명령어를 글자로 입력해서 컴퓨터를 부리는 프로그램. macOS 기본은 `zsh`.
- **터미널(terminal):** 그 셸을 띄워 놓고 글자를 주고받는 검은 창. "터미널처럼 생긴 곳"이 바로 이것.
- **VSCode (Visual Studio Code):** 마이크로소프트가 만든 무료 코드 편집기. 코드를 쓰고,
  터미널을 띄우고, 디버깅까지 한 창에서 한다.

## 1. 왜 코랩/주피터에서 ".py + VSCode"로 옮기나

코랩·주피터는 **셀(cell) 단위로 코드를 조금씩 실행**하며 결과를 바로 보는 데 강하다.
탐색·실험에는 좋지만, 연구 프로젝트를 굴리기 시작하면 다음이 불편해진다.

용어 풀이:

- **셀(cell):** 노트북에서 코드를 잘라 담는 한 칸. "이 칸만 실행" 식으로 부분 실행한다.
- **재현성(reproducibility):** 같은 코드를 나중에/다른 사람이 돌려도 같은 결과가 나오는 성질.
- **버전 관리(version control):** 코드의 변경 이력을 저장해 두는 것(여기선 git).

`.py` 파일 + VSCode로 옮기는 이유:

1. **재현성** — 노트북은 셀을 위아래로 마구 실행할 수 있어, "어떤 순서로 돌렸는지"가
   결과에 숨어든다. `.py` 스크립트는 위에서 아래로 한 번에 도는 게 기본이라
   `python 파일.py` 한 줄이면 항상 같은 순서로 재현된다.
2. **버전 관리(git)** — `.py`는 그냥 텍스트라 git이 줄 단위로 변경 이력을 깔끔히 관리한다.
   노트북(`.ipynb`)은 출력·메타데이터까지 섞인 큰 JSON이라 변경 비교(diff)가 지저분하다.
3. **서버 실행** — 연구실 GPU 서버에서는 보통 브라우저 노트북 대신
   `python scripts/이것.py ...`처럼 명령으로 돌린다(특히 ssh로 접속해 백그라운드로
   오래 돌릴 때). `.py`로 짜 두면 로컬에서 짠 코드를 서버에서 그대로 실행할 수 있다.

핵심 전략은 **"탐색은 노트북처럼, 완성은 스크립트로"** 이다.
VSCode는 둘 다 한 파일 안에서 가능하게 해 준다(아래 7절 Interactive Window).

## 2. VSCode 설치 + 확장(Python, Pylance)

### 2-1. VSCode 설치

- **무엇을:** VSCode 본체를 맥에 설치한다.
- **왜:** 코드 편집·실행·디버깅·터미널·서버 접속을 한 창에서 하기 위해.
- **어떻게:** 브라우저에서 `https://code.visualstudio.com` 접속 → "Download for macOS"
  → 받은 `.zip`을 더블클릭하면 `Visual Studio Code.app`이 나온다 →
  그 앱을 **응용 프로그램(Applications)** 폴더로 끌어다 놓고, 거기서 실행한다.

선택: 터미널에서 `code` 명령으로 폴더를 열고 싶다면, VSCode 안에서
`Cmd+Shift+P`(명령 팔레트) → `Shell Command: Install 'code' command in PATH` 실행.

용어 풀이:

- **명령 팔레트(Command Palette):** VSCode의 만능 검색창. `Cmd+Shift+P`로 열고,
  하고 싶은 동작 이름을 글자로 쳐서 찾아 실행한다. 메뉴를 못 찾겠으면 여기서 검색하면 된다.

### 2-2. 확장(Extension) 설치 — Python, Pylance

VSCode 본체는 텍스트 편집기일 뿐이다. 파이썬 실행 버튼, 자동완성, 오류 표시,
디버깅 같은 기능은 **확장(추가 기능)** 이 붙여 준다. 우리에게 필요한 건
`Python`과 `Pylance`(둘 다 Microsoft)이다.

**가장 쉬운 길 — 추천 확장 알림 받기:** 이 레포에는 `.vscode/extensions.json`에
필요한 확장 목록(`Python`, `Pylance`, `Jupyter`, `Remote - SSH`)이 미리 적혀 있다.
그래서 **3절처럼 이 폴더를 열면**, VSCode가 오른쪽 아래에 "이 워크스페이스에 추천하는
확장을 설치할까요?(Do you want to install the recommended extensions...)" 알림을
띄우는 게 보통이다. 거기서 **Install** 한 번이면 위 확장이 한꺼번에 깔린다.
(알림이 안 뜨면 아래 수동 방법을 쓰면 된다. 폴더 열기는 3절 참고.)

**수동으로 설치(설치 위치를 그림말로):**
1. VSCode 왼쪽에 세로로 늘어선 아이콘 줄이 있다(이걸 **액티비티 바**라 한다).
2. 그중 **네모 4개 중 하나가 떨어져 나가는 모양**(블록 아이콘)을 클릭 →
   **확장(Extensions)** 패널이 열린다. 단축키는 `Cmd+Shift+X`.
3. 위쪽 검색창에 `Python`을 친다 → 발행자가 **Microsoft**인
   **"Python"** 확장을 골라 **Install**.
4. 같은 방법으로 `Pylance`를 검색해 **Microsoft**의 **"Pylance"**도 Install.
   (Python 확장을 깔면 Pylance가 함께 따라오는 경우가 많다. 배포 시점에 따라
   별도 설치가 필요할 수 있으니, 안 깔려 있으면 직접 깐다.)

용어 풀이:

- **확장(Extension):** VSCode에 기능을 더하는 플러그인.
- **Python 확장:** 파이썬 코드 실행·디버깅·인터프리터 선택·테스트 등을 담당.
- **Pylance:** 코드 자동완성, 타입 힌트, 오류 미리 표시(빨간 밑줄) 등을 담당하는 "언어 도우미".

## 3. 프로젝트 폴더 열기

VSCode는 **파일 하나**가 아니라 **폴더(프로젝트) 단위**로 여는 게 정석이다.
폴더를 열어야 터미널의 현재 위치, 가상환경, git이 그 폴더 기준으로 맞물린다.

- **무엇을:** 우리 레포 폴더를 통째로 연다.
- **왜:** 스크립트 경로(`scripts/...`), 가상환경(`.venv`), git이 모두 이 폴더를
  기준으로 동작하게 하려고.
- **어떻게:** 상단 메뉴 **File > Open Folder...** →
  `~/projects/epitope-guided-docking` 선택 → **Open**.
  - 처음 열면 작성자를 신뢰하느냐는 프롬프트(예: "Do you trust the authors of the
    files in this folder?")가 뜰 수 있다. 내 폴더이므로 신뢰(Yes/Trust)를 고른다.
  - 왼쪽 **탐색기(Explorer, 종이 두 장 아이콘 / `Cmd+Shift+E`)**에
    `docs/`, `scripts/` 등 폴더 트리가 보이면 성공.
  - 이때 2-2에서 말한 "추천 확장 설치" 알림이 같이 뜰 수 있다. 아직 확장을 안 깔았으면
    여기서 **Install** 하면 된다.

## 4. 가상환경(venv) 만들기·활성화·선택

### 4-1. 가상환경이 뭔가

- **가상환경(virtual environment, venv):** 이 프로젝트만 쓰는 **독립된 파이썬 + 패키지
  상자**. 프로젝트마다 필요한 라이브러리 버전이 다른데, 시스템 전체에 막 깔면 서로
  충돌한다. venv는 그 충돌을 막아 주고, "이 프로젝트는 이런 패키지로 돌아간다"를
  깔끔하게 분리·재현하게 해 준다.
- **패키지(package) / 라이브러리(library):** 남이 만들어 둔 파이썬 기능 묶음
  (예: `numpy`, `pandas`). `pip`으로 설치한다.
- **`pip`:** 파이썬 패키지 설치 도구.

### 4-2. 만들기 + 활성화 + 설치

먼저 VSCode에서 **통합 터미널**을 연다(5절에서 자세히): 상단 메뉴
**Terminal > New Terminal**. 터미널의 현재 위치가 프로젝트 폴더인지 확인하고 다음을 친다.

```bash
# 1) 이 폴더 안에 .venv 라는 가상환경을 만든다 (한 번만)
python3 -m venv .venv

# 2) 가상환경을 켠다(활성화). 켜지면 프롬프트 앞에 (.venv) 가 붙는다
source .venv/bin/activate

# 3) 이 레포에는 requirements.txt 가 있으므로 한 번에 설치한다
pip install -r requirements.txt
```

설명:

- `python3 -m venv .venv` — 현재 폴더에 `.venv`라는 숨김 폴더를 만들고 그 안에
  전용 파이썬을 복사해 둔다. 점(`.`)으로 시작해서 보통 Finder/탐색기에서 가려진다.
  - 참고: macOS에 기본 내장된 `python3`은 버전이 오래된 편이다(이 맥은 3.9.x).
    그대로 써도 이 레포 스크립트는 돌아가지만, 더 새 버전을 쓰고 싶으면 `pyenv`나
    Homebrew의 `python` 등으로 따로 설치한 파이썬으로 venv를 만들면 된다.
    **연구실 서버의 파이썬 버전은 다를 수 있으니 서버에서는 그쪽 기준으로 다시 만든다.**
- `source .venv/bin/activate` — 이 터미널에서 앞으로 `python`/`pip`을 치면
  시스템 것이 아니라 `.venv` 안의 것을 쓰도록 "전환"한다. 프롬프트 왼쪽에 `(.venv)`가
  뜨면 켜진 것. 끌 때는 `deactivate`.
- `pip install -r requirements.txt` — `requirements.txt`에 적힌 패키지 목록을 한 번에 설치.
  (현재 이 레포의 `requirements.txt`에는 `numpy`, `pandas`, 구조 파일 처리용 `gemmi`,
  fallback용 `biopython`이 들어 있다.)
  - 새 패키지를 추가로 깔았으면 `pip install 이름` 으로 설치하고, 목록을 갱신하려면
    `pip freeze > requirements.txt` 로 현재 설치 상태를 파일에 다시 적으면 된다.
    (단, `pip freeze`는 의존 패키지까지 전부 적으므로, 직접 손으로 핵심만 정리하는
    방식도 흔하다.)

용어 풀이:

- **프롬프트(prompt):** 터미널에서 명령을 기다리는 줄. 보통 `$`(또는 `%`)로 끝난다.
  가상환경이 켜지면 그 앞에 `(.venv)`가 붙는다.

### 4-3. VSCode가 이 가상환경을 쓰게 "인터프리터 선택"

- **무엇을:** VSCode가 코드를 실행/검사할 때 쓸 파이썬을 `.venv`로 지정한다.
- **왜:** 터미널에서 `activate` 했어도, VSCode의 실행 버튼·디버거·자동완성은 별도로
  "어느 파이썬을 쓸지" 알아야 한다. 안 맞추면 "패키지를 깔았는데 import가 안 된다"가 생긴다.
- **인터프리터(interpreter):** 파이썬 코드를 실제로 해석·실행하는 프로그램 본체.
- **참고(이 레포는 미리 설정돼 있음):** 이 레포의 `.vscode/settings.json`에는
  `python.defaultInterpreterPath`가 `.venv/bin/python`으로,
  `python.terminal.activateEnvironment`가 켜짐으로 적혀 있다. 그래서 `.venv`를 만든 뒤에는
  VSCode가 **자동으로 `.venv`를 골라 주고, 새 터미널을 열 때 자동 활성화**해 주는 경우가
  많다. 그래도 아래로 한 번 확인/지정해 두면 확실하다.
- **어떻게(둘 중 하나):**
  - 명령 팔레트(`Cmd+Shift+P`) → `Python: Select Interpreter` →
    목록에서 `.venv` 경로(예: `./.venv/bin/python`, 보통 "Recommended" 표시)를 선택.
  - 또는 VSCode **오른쪽 아래 상태 표시줄**에 보이는 파이썬 버전 글자를 클릭해도 같은 목록이 뜬다.

## 5. "터미널처럼 생긴 곳"의 정체 = 통합 터미널

VSCode 아래쪽에 뜨는 검은 입력창이 **통합 터미널(Integrated Terminal)** 이다.
별도 터미널 앱을 띄울 필요 없이, **편집 중인 프로젝트 폴더 안에서** 명령을 칠 수 있다.

- **무엇을:** VSCode 안에서 셸 명령을 실행한다.
- **왜:** 스크립트 실행, 가상환경 활성화, git 명령 등을 코드 옆에서 바로 하기 위해.
- **어떻게:**
  - 열기: 상단 메뉴 **Terminal > New Terminal**, 또는 단축키 **Ctrl + `**
    (백틱 `` ` ``. 보통 키보드 숫자 1 왼쪽, `~`와 같은 키).
  - 새 터미널은 보통 프로젝트 폴더에서 시작한다. 헷갈리면 `pwd`(현재 위치 출력)로 확인.

스크립트를 실행하는 기본 흐름(예시 — 이 레포에 **실제로 있는** `clean_af3_outputs.py`):

```bash
# (.venv) 가 켜져 있는지 먼저 확인. 없으면:
source .venv/bin/activate

# 1) 그 스크립트가 어떤 옵션을 받는지 먼저 확인 (이게 가장 안전한 첫 단계)
python scripts/clean_af3_outputs.py --help

# 2) 실제 실행. clean_af3_outputs.py 는 "기준 폴더"를 위치 인자로 받는다(점 앞에 -- 없음).
#    기본은 DRY-RUN(예행 연습)이라 무엇을 지울지 목록만 보여 주고 실제로는 안 지운다.
python scripts/clean_af3_outputs.py /경로/AF3_outputs

# 3) 목록을 확인하고 정말 지울 거면 --apply 를 붙인다 (이게 있어야만 실제 삭제)
python scripts/clean_af3_outputs.py /경로/AF3_outputs --apply
```

> 주의: 위 스크립트는 AF3 출력 폴더 아래의 `msas/`, `template/` 같은 보조 폴더를
> 재귀적으로 지운다. **반드시 먼저 `--apply` 없이 돌려 목록을 확인**한 다음 `--apply`를
> 붙여라. `--apply`가 곧 삭제 스위치다.

설명:

- `python scripts/clean_af3_outputs.py` — `scripts` 폴더의 그 `.py` 파일을 실행.
  경로는 **현재 위치(프로젝트 폴더) 기준의 상대경로**다.
- `/경로/AF3_outputs` — 이 스크립트는 기준 폴더를 **위치 인자(positional argument)**로
  받는다. 즉 `--base-dir` 같은 이름표 없이 그냥 경로만 적는다.
  (스크립트마다 인자 방식이 다르다. 어떤 건 `--옵션 값` 꼴, 어떤 건 위치 인자다.
  항상 `--help`로 그 스크립트의 정확한 사용법을 먼저 확인하라.)

> 참고: 레포 설계상 앞으로 추가될 스크립트(예: 피처 추출 `af3_extract_features.py`,
> 변환 `af3_convert.py`)가 다른 문서에 언급될 수 있다. **이들은 아직 만들어지지 않았을 수
> 있으니**, 실행 전 `ls scripts/`로 실제 존재 여부와 `--help`로 인자를 확인하라.
> 현재 `scripts/`에 실제로 있는 파일은 `clean_af3_outputs.py`, `cif_distance.py`,
> `alanine_scan_prep.py` 다.

용어 풀이:

- **인자(argument):** 프로그램을 실행할 때 같이 넘기는 입력값. `--이름 값` 꼴(옵션 인자)도
  있고, 이름표 없이 순서로 넘기는 위치 인자도 있다.
- **상대경로 / 절대경로:** 상대경로는 "지금 있는 폴더 기준"(예: `scripts/x.py`),
  절대경로는 "맨 위 `/`부터 전부 적은 길"(예: `/Users/.../scripts/x.py`).

## 6. 디버거·중단점(breakpoint) 기초

코드가 원하는 대로 안 돌 때, `print`를 잔뜩 박는 대신 **디버거**로 실행을 한 줄씩
멈춰 가며 변수 값을 들여다볼 수 있다.

용어 풀이:

- **디버거(debugger):** 프로그램을 멈춰 세우고 내부 상태(변수 등)를 살펴보는 도구.
- **중단점(breakpoint):** "여기서 멈춰라"라고 코드에 찍는 표시.

기본 사용:

- **무엇을:** 특정 줄에서 멈추고, 그 시점의 변수 값을 확인한다.
- **왜:** 오류 원인이 어디서, 어떤 값 때문에 생기는지 정확히 보려고.
- **어떻게:**
  1. 멈추고 싶은 줄 번호 **왼쪽 여백**을 클릭하면 빨간 점이 찍힌다(= 중단점).
  2. **F5**를 누르면 디버그 실행이 시작된다.
     (처음엔 "어떻게 실행할지" 물으면 **Python File**(현재 파일 실행)을 고르면 된다.
     단, 디버거는 보통 인자 없이 파일을 실행하므로, `--help`나 `/경로` 같은 인자가
     필요한 스크립트는 `launch.json`에 `"args"`를 적어 줘야 제대로 돈다. 인자가 꼭
     필요하면 그냥 터미널에서 5절처럼 실행하는 게 간단하다.)
  3. 빨간 점 줄에서 실행이 멈추면, 왼쪽 **변수(Variables)** 패널에서 값들을 본다.
  4. 위에 뜨는 작은 막대의 버튼으로 진행을 제어한다:
     - **Continue(F5):** 다음 중단점까지 쭉 진행
     - **Step Over(F10):** 현재 줄 하나만 실행하고 다음 줄로
     - **Step Into(F11):** 함수 안으로 들어가서 따라가기
     - **Stop(Shift+F5):** 디버깅 끝

코드로 중단점을 거는 방법(클릭 대신):

```python
breakpoint()  # 이 줄에 도달하면 실행이 멈춘다
```

`breakpoint()`는 파이썬 기본 기능이라, 줄 여백 클릭이 어려운 상황(예: 서버에서
글자만 쓸 때)에서도 쓸 수 있다. 터미널에서 `python 파일.py`로 실행하다 이 줄을 만나면
`pdb`라는 글자 기반 디버거가 뜬다(`n`=다음 줄, `c`=계속, `q`=종료, `p 변수`=값 출력).

## 7. 코랩처럼 "조금씩 실행"하고 싶을 때 — Interactive Window (`# %%`)

코랩의 셀 실행이 그리우면, `.py` 파일 안에서도 똑같이 **셀 단위 실행**을 할 수 있다.
`.py` 안에 `# %%` 라는 줄을 넣으면 그 위아래가 **셀처럼** 나뉜다.

용어 풀이:

- **Interactive Window(인터랙티브 윈도):** VSCode가 `.py`를 노트북처럼 부분 실행해
  결과(그래프·표 포함)를 옆 창에 보여 주는 기능. 내부적으로 주피터 엔진을 쓴다.
  - 이 기능을 쓰려면 **Jupyter 확장**(2-2의 추천 목록에 포함)과, `.venv` 안에
    **`ipykernel`** 패키지가 필요하다. 처음 셀을 실행하면 VSCode가 `ipykernel`(때로
    관련 jupyter 의존성까지) 설치를 권하는 알림을 띄운다. 그 알림의 Install을 누르거나,
    `(.venv)`를 켠 터미널에서 직접 `pip install ipykernel` 하면 된다.
    (권장 알림 문구는 버전에 따라 다를 수 있다.)

쓰는 법:

```python
# %%
# 이 위~다음 # %% 까지가 한 "셀"이다
import numpy as np
x = np.arange(10)
x

# %%
# 다음 셀: 위에서 만든 x 를 그대로 이어서 쓸 수 있다
x.mean()
```

- **무엇을:** `.py` 안에서 셀처럼 일부만 골라 실행한다.
- **왜:** 데이터·결과를 눈으로 확인하며 탐색하기 좋다(코랩 장점 유지).
- **어떻게:** `# %%` 윗줄에 나타나는 작은 회색 글씨 **Run Cell**을 클릭하거나,
  셀 안에 커서를 두고 **Shift+Enter**. 결과는 Interactive Window 창에 뜬다.

권장 흐름:

- **탐색 단계:** `# %%`로 잘라 가며 셀처럼 돌려 본다.
- **완성 단계:** 흐름이 잡히면 `# %%` 주석은 그냥 두거나 지우고, 위에서 아래로
  한 번에 도는 **평범한 스크립트**로 정리한다 → `python 파일.py`로 실행/서버 이관.
  (`# %%`는 그저 주석이라, 그대로 둬도 `python`으로 통째 실행하는 데 지장 없다.)

## 8. 연구실 서버에서 직접 편집·실행 — Remote-SSH (개요)

로컬 맥이 아니라 **연구실 리눅스 서버 위의 파일을 VSCode로 열고, 서버에서 바로 실행**할 수
있다. 이때 쓰는 확장이 **Remote - SSH** 다.

용어 풀이:

- **ssh:** 내 컴퓨터에서 멀리 있는 서버에 안전하게 접속하는 방법.
- **Remote - SSH:** VSCode를 그 원격 서버에 "붙여서", 서버의 폴더를 마치 로컬처럼
  편집·실행하게 해 주는 확장. 코드가 서버에서 돌아가므로 서버의 GPU·데이터를 바로 쓴다.

개요만(세부 단계·프롬프트 문구는 확장 버전에 따라 다를 수 있다):

1. 확장 패널(`Cmd+Shift+X`)에서 `Remote - SSH`(Microsoft) 설치.
   (2-2의 추천 확장 목록에 이미 들어 있어, 폴더 열 때 함께 깔렸을 수 있다.)
2. 명령 팔레트(`Cmd+Shift+P`) → `Remote-SSH: Connect to Host...` →
   서버 주소 입력해 접속(예: `<USER>@<YOUR_SERVER_IP>`).
3. 새 VSCode 창이 서버에 연결되면 **File > Open Folder**로 서버의 작업 폴더를 연다.
   이후 편집·터미널·실행이 전부 **서버 안에서** 일어난다.
   - 주의: Remote-SSH로 붙으면 확장·인터프리터·`.venv`도 **서버 쪽 것**을 따로 골라야 한다.
     로컬 맥의 `.venv`는 서버에서 쓸 수 없으니, 서버에서 4절을 다시 한 번 한다.

상세 설정(접속 정보 관리, 키 등록, `scp`로 파일 전송, `tmux`로 오래 도는 작업 유지)은
`docs/03_서버_ssh_scp_tmux.md`를 참고한다. (서버 IP/포트/계정 같은 민감정보는 문서에
적지 말 것 — `<YOUR_SERVER_IP>`, `<PORT>`, `<USER>` 같은 자리표시자만 사용.)

## 9. 로컬에서 돌릴까, 서버에서 돌릴까

매번 어디서 돌릴지 헷갈리면, 다음 두 가지만 따져 본다.

1. **데이터가 어디 있나**
   - 처리할 입력 데이터(예: AF3 출력 폴더, 큰 `.cif`/`.json` 묶음)가 **서버에** 있으면
     서버에서 돌리는 게 맞다. 큰 데이터를 로컬로 끌어오는 것 자체가 느리고 번거롭다.
   - 작은 결과 표/그림 정리, 코드 작성·디버깅 정도면 로컬이 편하다.

2. **GPU가 필요한가**
   - **GPU(그래픽 처리 장치):** 딥러닝 모델 추론·학습을 빠르게 돌리는 하드웨어.
   - PLM 임베딩 추출(ESM-2 등)이나 무거운 모델 추론처럼 **GPU가 필요한 작업은 서버**에서.
   - 가벼운 분석(표 합치기, 상관계수 계산, 그림 그리기, 소규모 모델)은 로컬도 충분.

요약 기준:

- **로컬(맥):** 코드 작성·디버깅, 작은 데이터·결과 분석, GPU 불필요.
- **서버:** 데이터가 서버에 있음, GPU 필요, 오래 도는 작업(이때 `tmux`로 세션 유지 →
  `docs/03_서버_ssh_scp_tmux.md` 참조).

실전 권장: **로컬에서 `.py`를 깔끔히 짜고 git에 올린 뒤, 서버에서 내려받아(pull) 실행**.
이러면 같은 코드를 양쪽에서 일관되게 굴릴 수 있다.
(주의: `.gitignore`가 `data/`, `*.cif`, `*.json` 같은 큰/미공개 파일은 일부러 제외하므로,
**데이터는 git이 아니라 `scp`/서버 경로로** 옮긴다 → `docs/03_서버_ssh_scp_tmux.md`.)

## 10. git에 올리기 (한두 줄 요약)

코드가 한 덩어리 정리되면, 변경 이력을 저장하고 서버/원격에 공유한다.

```bash
git add -A          # 바뀐 파일 전부 무대에 올림
git commit -m "메시지"   # 변경 묶음을 이력으로 저장
git push            # 원격(GitHub 등)으로 올림 → 서버에서 git pull 로 받음
```

(git 자체의 자세한 사용법은 이 문서 범위 밖. 위 세 줄이 가장 기본 흐름이다.
미공개 연구실 데이터·문서는 커밋하지 않도록 `.gitignore`가 막아 두었으니,
새 파일을 올릴 때 민감 데이터가 섞이지 않았는지 `git status`로 한 번 확인하라.)

## 부록: 자주 막히는 지점 빠른 점검

- **`command not found: python`** → `python3`을 쓰거나, `.venv` 활성화 후 `python` 사용.
- **패키지 깔았는데 `ModuleNotFoundError`** → VSCode 인터프리터가 `.venv`인지 확인
  (`Python: Select Interpreter`), 터미널에 `(.venv)`가 떠 있는지 확인.
- **터미널이 엉뚱한 폴더에 있음** → `pwd`로 확인, 필요하면 프로젝트 폴더를 다시 Open Folder.
- **스크립트가 인자 오류를 냄(`unrecognized arguments` 등)** → 그 스크립트의 인자 방식이
  `--옵션`인지 위치 인자인지부터 `python scripts/이름.py --help`로 확인.
  (예: `clean_af3_outputs.py`는 `--base-dir`가 아니라 위치 인자로 경로를 받는다.)
- **`# %%` 셀 실행이 안 됨** → Jupyter 확장 설치 + `(.venv)`에서 `pip install ipykernel`.
- **숨김 폴더 `.venv`가 안 보임** → 점으로 시작하는 폴더는 Finder에서 기본적으로 가려진다(정상).
  VSCode 탐색기에서는 보통 보인다.
